# Migration to v1.16.0

See [`README.md`](README.md) for the deprecation-cycle policy.

## Summary

- **Monomorphic rename** for `movemask` (the polymorphic form still works
  but emits a deprecation warning at every call site).
- Additive: `movemask_u64x4` (x86), `nibble_mask_u8x16` (ARM),
  `ctz_u32` / `ctz_u64` (cross-platform).

The breaking-removal cycle for `movemask` completes in **v2.0.0**, together
with the v1.12.0 batch.

## Breaking changes (deprecation warnings, not removals)

### Item: `movemask` → typed spellings

- **Why:** same rule as v1.12.0 — every intrinsic carries its type in the
  name. The typed spellings also return `u32` instead of `i32`, so a mask
  feeds straight into `ctz_u32` and `m & (m - 1)` without a cast.
- **Deprecation cycle:** warning emitted from v1.16.0; removal scheduled
  for v2.0.0.
- **Migration recipe:**

  ```ea
  // Before:
  let m: i32 = movemask(bytes .== splat(60))      // bytes: u8x32

  // After (x86 kernel):
  let m: u32 = movemask_u8x32(bytes .== splat(60))

  // After (*_arm.ea kernel) — ARM has no pmovmskb; use its native idiom:
  let m: u64 = nibble_mask_u8x16(bytes .== splat(60))   // bytes: u8x16
  let first: i32 = ctz_u64(m) / 4                       // 4 bits per lane
  ```

  | Polymorphic name | Typed spellings |
  | --- | --- |
  | `movemask(v)` (x86-only) | `movemask_u8x16`, `movemask_u8x32` (x86-only); ARM counterpart `nibble_mask_u8x16` |

  Codegen is unchanged: the typed x86 spellings use the same `pmovmskb`
  lowering (verified byte-identical asm across 25 consumer kernels).

- **Warning text emitted at the polymorphic call site:**

  ```
  warning: intrinsic 'movemask' is deprecated since 1.16.0 — use the typed
  spelling: movemask_u8x16 / movemask_u8x32 (x86-only); on ARM use
  nibble_mask_u8x16 (at line N, column N)
  ```

- **Affects:** `Olorin`, `eaclaw`, `eachacha`, `eastat`, `eabrain`. Grep
  `.ea` sources for `movemask(` and switch to the typed spellings before
  v2.0.0. Where the result was compared or combined with `i32` values, the
  new `u32` result type may need the surrounding variables changed to `u32`.
