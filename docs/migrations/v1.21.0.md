# Migration to v1.21.0

See [`README.md`](README.md) for the deprecation-cycle policy.

## Summary

- **Typed native forms** replace two generic intrinsics that LLVM emulated:
  `gather` and `load_masked` / `store_masked`. The generic forms still work
  but emit a deprecation warning at every call site.
- **Comparison masks record their source type** (`mask<T>xN`), so masks can
  be combined with `.&`, `.|`, `.^`. Existing programs keep compiling.
- Additive: `to_u64`, `andnot_*`, `floor_f32x4/x8`, `bitcast_f32x4/x8`,
  `bitcast_u8x32`, `bitcast_i16x16`, `widen_u8x16_u16x16`.

The removal cycle for `gather`, `load_masked` and `store_masked` completes
in **v2.0.0**, together with the v1.12.0 and v1.16.0 batches.

## Breaking changes (deprecation warnings, not removals)

### Item: `gather` → `gather_i32x4` / `gather_i32x8` / `gather_f32x4` / `gather_f32x8`

- **Why:** the generic form lowered to `llvm.masked.gather`, which LLVM
  scalarizes on x86-64-v3 (one `vpextrd`/`vpinsrd` pair a lane instead of
  one `vpgatherdd`). Eä intrinsics are native or an error.
- **Deprecation cycle:** warning from v1.21.0; removal in v2.0.0.
- **Migration recipe:**
  ```
  let v: i32x8 = gather(table, idx)        // before
  let v: i32x8 = gather_i32x8(table, idx)  // after
  ```
  Other element types (`u8`, `i16`, `f64`, ...) have no gather
  instruction: load those lanes with scalar loads and compose them. On ARM
  every gather is a compile error (see `docs/idioms/neon-gather.md`).

### Item: `load_masked` / `store_masked` → `load_masked_<t>` / `store_masked_<t>`

- **Why:** AVX2 has masked loads and stores only for 32- and 64-bit lanes,
  NEON has none; LLVM emulated the rest.
- **Deprecation cycle:** warning from v1.21.0; removal in v2.0.0.
- **Migration recipe:**
  ```
  let w: i32x4 = load_masked(p, 0, n)            // before
  let w: i32x4 = load_masked_i32x4(p, 0, n)      // after (x86)
  store_masked_i32x4(p, 0, w, n)
  ```
  Typed forms exist for `i32x4`, `i32x8`, `f32x4`, `f32x8`, `u64x4`. For
  `u8`/`i16` lanes and on ARM, copy the tail into a buffer padded to a whole
  vector and use plain `load` / `store`.
